01

整体架构设计

前端 · 后端 · 数据存储 · 部署方式的选择与理由

核心判断：这是一个个人情感场景、无登录、单次分享的小型站点，访问量与并发极低。因此架构目标是「极简可维护」而非「高并发可扩展」——能零成本部署、能在本机一行命令更新，就是最优解。据此采用渐进式架构：先纯前端跑通，再按需叠加服务端能力。

前端
单页应用：HTML + CSS + 原生 JS（Canvas / DOM + CSS 动画）
不引入 React/Vue 等框架。理由：页面交互逻辑集中在"星空渲染 + 点亮 + 卡片"三块，原生实现体积小（单文件 <50KB）、无构建步骤，本机直接改文件即可维护。星空用 DOM 元素便于做逐星动画与点击，百级规模性能无压力。
后端
阶段一：无后端（纯前端） ／ 阶段二：Serverless 函数（可选）
阶段一无需服务器：冷却走本地存储，AI 由浏览器直连大模型接口。阶段二如需"跨设备防绕过"或"隐藏 API Key"，再加一个 Serverless 函数（华为云 FunctionGraph / Cloudflare Workers），仅承担「AI 代理」与「冷却状态读写」两件事，不引入常驻服务器。
数据存储
素材：静态 JSON（records.json）；冷却状态：localStorage（可选 KV）
素材以「编号 → 文本」的稀疏 Map 存储，编号本身就是 key，天然支持缺号 / 跳号；渲染时遍历 1–100，无对应 key 的位置渲染为"待补充空位"。冷却状态存本机 localStorage；如需服务端，用 Serverless 附带 KV / 轻量数据库。
部署
GitHub Pages（主）＋ jsDelivr CDN 镜像（国内访问）
零成本、免运维，本机 git push 即完成更新，链接永久不变。国内访问不稳定时，用 jsDelivr CDN 生成国内可访问的镜像链接（已验证为本场景最稳方案）。也可选华为云 OBS 静态托管 / 云函数。
02

冷却机制实现方案

本地存储 vs 服务端识别，以及「无登录下如何识别同一访问者」

需求要"同一访问者需间隔一定时间才能点亮下一颗"。难点在于：没有登录体系，如何定义"同一访问者"？本质是"用什么标识去绑定一条冷却记录"。下面先横向对比，再给结论。

方案优点缺点结论
localStorage 零成本、零延迟、无需服务器；数据不出本机，隐私友好；实现最简单 清缓存 / 换浏览器 / 无痕模式可绕过；仅单设备有效 首选默认
Cookie 可设过期时间，服务端也能读到；比 localStorage 稍"正式" 容量小（4KB）；同样可被清除；跨域场景受限 备选
服务端 + 设备指纹 难绕过、可跨浏览器统计；可做风控 需后端与存储；指纹有隐私争议与误判；部署维护成本上升 可选增强
服务端 + 账户登录 最严格，天然跨设备 需注册登录，破坏"点开链接就玩"的浪漫体验 不推荐
结论：这是给恋人的私人小站，防作弊不是目的，"让 TA 慢慢点亮、把节奏拉长"才是目的。因此默认采用 localStorage 方案——同一浏览器即视为"同一访问者"，冷却状态存本地。若被清缓存"绕过"，损失的只是仪式感，并不影响体验公平性，故无需付出后端复杂度。

无登录下如何识别「收到链接的同一访问者」

  • 阶段一（默认）：浏览器实例 = 访问者。localStorage 存 { lit: [已点亮编号], lastLitAt: 最后点亮时间戳 }，读取 lastLitAt 与当前时间差判断是否在冷却期。
  • 阶段二（可选）：若要防"换浏览器重置"，由 Serverless 用弱指纹（Canvas 指纹 + UA + 屏幕尺寸 + 时区）生成匿名设备 ID，配合链接唯一 token（?gift=<token>）落库。代价是需引入后端与隐私说明，仅在你明确要求"更严格"时启用。
  • 不做：强制登录 / 手机号验证。会显著抬高 TA 的进入门槛，与"温馨、无压力"的定位冲突。

冷却可配置设计

  • 代码顶部统一 CONFIG.COOLDOWN_SECONDS：测试期设为 300（5 分钟），上线可改 30 分钟 / 1 小时 / 1 天。无需改逻辑，只改一个数字。
  • 配套开关 LOCK_OTHERS_DURING_CD：冷却期间是否把其余星星置灰锁定（原型默认开启，视觉上强化"等待感"）。
  • 管理侧可另做隐藏入口（如 URL 加 ?admin=1）一键重置冷却，便于你自测。
03

大模型 API 接入方案

用途 · 接入方式 · 调用位置 · 成本 · 异常降级

在本项目中的具体用途

  • 情话回信：TA 点亮一颗星、读完那段回忆后，可点「生成情话回信」，由大模型基于该条记录的内容写一句专属回应（不是套话模板）。这是最贴合情感场景的用法。
  • 周年总结（彩蛋）：集齐/点满若干颗后，把所有记录喂给模型，生成一段"我们的 100 天总结"。
  • 不做的事：不用 AI 替你们"编写回忆"。回忆必须是你亲手写的真实素材，AI 只负责"回应"与"润色氛围"，守住真诚的底线。

接入方式与调用位置

  • 服务商（默认建议）：DeepSeek（成本极低、国内直连稳定、OpenAI 兼容接口）或阿里云通义千问。均采用 OpenAI 兼容协议，便于日后一行切换服务商。
  • 调用位置：记录卡片内的「生成情话回信」按钮 → 触发一次 chat 请求，prompt 注入「当前记录原文 + 关系语境」，返回文本填入卡片。
  • 两种接入形态：①前端直连（个人场景，最省事，但 API Key 会出现在浏览器）；②Serverless 代理（Key 存服务端环境变量，前端只调你的函数，更安全，需多部署一个函数）。默认建议先直连跑通，若要分享扩散再切代理。

调用成本

  • DeepSeek 约 ¥1 / 百万 tokens 量级，单次"情话回信"（输入+输出约 300 tokens）成本约 ¥0.0003。
  • 即便 100 条记录每次都被生成，总成本也 不足 ¥0.05，可忽略。真正的约束是"避免滥用"而非费用。

异常降级策略

  • 超时 / 失败 / 未配置 Key：自动回退到本地预置文案库（每条记录可配 1–2 句手写祝福，随机取一句），保证"永远有回应"，页面绝不报错。
  • 请求节流：同一记录短时间内重复点击不重复计费；加 loading 态与 3 秒超时。
  • 降级可见但不突兀：兜底文案与 AI 文案在体验上保持一致，用户无感。
04

适用场景与使用流程

从"你准备素材"到"TA 逐颗点亮"的完整路径

1
你：准备素材并部署
整理 100 条相处记录（编号 + 文本，可缺号），填入 records.json → 部署到公网 → 得到一条链接。
2
你：把链接发给 TA
通过微信等任意渠道发送，附一句"送你 100 颗星星"。链接可带专属 token，便于日后区分是否为 TA 的访问。
3
TA：打开即见星空
无需注册、无需下载。首屏是一片深粉夜空与 100 颗微光星，顶部显示「已点亮 0 / 100」。
4
TA：点亮第一颗星
轻触任意微光星 → 星光爆闪 + 轻柔铃音 → 弹出卡片，逐字浮现那段回忆 → 可点「生成情话回信」看 AI 回应。
5
冷却循环：每 5 分钟一颗
点亮后底部进入倒计时，其余星星锁定置灰。冷却结束才能再点亮——把"一次读完"变成"慢慢期待"。
6
进度累积 → 彩蛋
进度逐步向 100 迈进，集满时触发专属彩蛋（如全屏星光 + AI 生成的百天总结 + 一段隐藏祝福）。
为什么要把节奏拉长？若 100 颗星一次性全部点亮，用户会在 10 分钟内看完随后遗忘。冷却机制把"纪念碑"变成了 "每天回来看看的日常仪式"——这才是纪念日产品真正的价值：让 TA 反复想起你。
05

方案的可维护性

替换素材 · 调整冷却 · 重新部署，均由本机完成

替换 / 新增素材

  • 只编辑 records.json："12": "文本…"，编号为 key。
  • 新增：加一行即可；删除：删一行；缺号 / 跳号天然支持，对应位置自动渲染为"待补充空位"，不影响其余星星。
  • 改完 git push，刷新链接即生效——链接不会变，无需重新分享。

调整冷却时间

  • 改 CONFIG.COOLDOWN_SECONDS 一个数字：测试 300 → 上线可改 1800 / 3600 / 86400。
  • 可选提供 ?admin=1 管理入口，一键清空本地冷却与点亮记录，方便你自己反复测试。

重新部署

  • 本机执行 npm run deploy（封装 git push）或直接 git push，GitHub Pages 自动重建。
  • 预计 30 秒内生效，公网链接保持不变。
  • 项目目录结构建议：index.html（页面）、records.json（素材）、config.js（冷却/AI 配置）、README.md（维护说明）。

交互稿思路与动效说明

粉色系 · 少女心 · Kitty 装饰，以及每处动效的选择理由

交互原型已同步产出（链接见交付说明），可点击体验。整体视觉采用深粉夜空 + 暖粉星光：背景是深紫粉渐变夜空，右上角一轮柔光月亮，角落点缀粉色小猫（蝴蝶结 + 圆脸 + 胡须的抽象形象）作为背景装饰，不喧宾夺主。

关键动效及其选择理由

  • 未点亮星：微光呼吸。每颗暗星以随机相位缓慢明灭，让"星空是活的"，暗示"它们在等你"。理由：静态星空缺乏邀请感，呼吸光营造"等待被点亮"的期待。
  • 点亮瞬间：星光爆闪 + 八向射线 + 合成铃音。点击后星光从星核向外绽放，同时用 Web Audio 合成一段轻柔三音阶铃音。理由：给"点亮"一次郑重的仪式感；音效用代码合成而非外部音频文件——体积为零、无版权风险、不受网络影响。
  • 记录卡片：弹性缩放入场 + 文字逐字渐显（blur→清晰）。理由：逐字浮现模拟"有人在耳边慢慢把这段话念给你听"，比整段直接显示更温柔、更有情绪节奏。
  • 已点亮星：缓慢漂浮 + 持续柔光。理由：与暗星形成"已点亮 / 待点亮"的视觉区分，一眼看清进度。
  • 冷却期：底部倒计时条 + 其余星星置灰锁定。理由：把"不能点"的原因可视化，等待变成可见的期待，而非困惑。
动效原则：克制而不堆砌。全场只保留"点亮"这一处高光时刻，其余动效都放慢、放柔，让每一次点亮都值得。避免过多花哨特效——那会让温馨感变成廉价感。适配：星空区使用方形自适应容器 + clamp() 字号，覆盖手机 / 平板 / 桌面；并尊重系统「减少动态效果」偏好。
